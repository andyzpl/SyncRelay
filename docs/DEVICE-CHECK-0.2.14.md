# 0.2.14 图片捕获验证

本轮只验收图片来源读取、资源校验和实际图片预览。图片发送仍关闭；已经跑通的单群文字实验保留原来的门禁和持久占位，不清除旧记录，也不重发旧来源。无需测试 100/200 个群。

## 安装

覆盖升级普通 DEB，不卸载、不清配置。重新启动微信，在「我 → 设置 → SyncRelay 转发 → 运行诊断」确认版本 `0.2.14`，并核对随包的源码提交/CI run。

## 最小测试

1. 选一个授权母群、一个非母群的目标群规则。来源成员先只选“我”；关闭“转发文字”，只保留“图片（仅捕获预览）”，点击“保存”。这一步可以避免文字先占用来源。
2. 点击“等待源消息 → 开始等待（不发送）”，回到母群，手动发送一张容易辨认的普通静态图片。测试期间不要锁屏或切后台；不用 GIF、表情、视频或“文件”形式的图片。
3. 返回设置，打开“源消息预览”，检查类型为 image、发送者是自己的 wxid，再点“消息内容”打开实际图片，核对是否确实为刚发的图片、方向是否正确。不能仅凭“已锁定 1 条”就判断图片正确。
4. 第一次先“放弃这条预览”；重新开始等待，手动发一张新图，确认另一张图片能被捕获，不串用旧缓存。
5. 第二次可以点“确认内容，建立计划（不发送）”。退出并重启微信，到“内容计划与历史”打开同一计划，检查仍能打开同一张图。确认和重启都不应发送任何图片或执行规则。

## 补充测试

- 将来源成员改为一个同意参与测试的其他 wxid，保存并重新等待；让该成员发一张图。未选中的其他成员发图应被过滤，不抢占图片等待。
- 关闭图片、只选文字，等待一条新的普通文字，核对原文字预览仍正常。没有必要再次开启主动文字实验。
- 图片资源未就绪时会等待。约 30 秒后仍不可用则停止，不伪造预览。可在母群先点开图片加载，之后重新开始等待并手动发送一张新图；本版不回扫旧消息或自动下载。
- 等待图片时手动取消、切后台或更换来源并重新保存后，旧回调不得进入新预览。不要为了测试账号切换而删除应用数据。

## 无法抓取时

失败当次立即导出 JSON，告诉开发者“本人/其他人、图片是否已在母群点开、是否等到超时、是否出现实际预览”。请勿手动编辑 JSON，也不必发送图片本身。

关键字段：`imageSource.getterABICompatible/state/reads`、`receiveCandidate.imageState/imageReads/imagePending/imagePreparationCode/counters`、`sourceCapture`。准备错误分类：1 无效或超限数据、2 自有目录不可用、3 配额、4 写入、5 来源范围、6 文件不可读、7 完整性、8 尺寸/动画、9 描述符或其他准备错误、10 异常、101 原生图片接口。错误报告不包含图片、原始 wxid/群 ID、路径、图片哈希或下载凭据。

如果提示缺少图片 getter 或 ABI 不兼容，停止图片测试并导出诊断，不安装 Mikoto 来补接口，不更改安全门禁。打包成功不代表这台手机上的图片链路已通过。
