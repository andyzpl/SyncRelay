# 0.2.5 方向字段定点真机检查

日期：2026-10-21。目的：定位 0.2.4 报告中的 `receive_wrong_direction` / `outgoing_wrong_direction`，不是转发验收。本包仍不向目标群发消息，也不放宽来源校验。

## 当前证据与包状态

旧报告来自 iOS 16.0.3、微信 8.0.79.35：保存后可等待，母群会话参数匹配，两个回调入口各观察到一次，但 from/to 方向校验拒绝，源捕获 offered 为 0。不能据此确定某个字段为空、账号 ID 不同或宿主改写了字段；本版补充关系证据后再判断。

0.2.5 正准备构建，编译提交、run、哈希、已通过测试和产物路径将在核验后补录。不要将 0.2.4 旧包当作本轮新包。

## 手机只做这几步

1. 替换为 0.2.5 后完全结束微信再打开，确认插件版本。升级不应清空已保存草稿，不必重建分组。
2. 保留原母群及小范围目标规则，确认来源勾选“我”且文字已启用，保存草稿。此次不更换母群、不用图片混测，先排除多项条件同时变化。
3. 手动开始等待，关闭插件面板回母群（不要退出微信），发送一条普通文字并记下大概时间；保持微信前台，不锁屏。
4. 无论是否捕获成功，回到「我 → 设置 → SyncRelay 转发 → 更多设置 → 导出运行诊断」。不要先停止后重开等待或重启微信，以免清空本轮方向样本。
5. 回传 JSON，说明本人发送时间、是否有预览、提示原文。无需提供正文、真实 wxid、群 ID 或聊天截图。

## 报告验收

- 插件版本为 0.2.5，build 中应有确切提交和 CI run，不能是 working-tree/local。
- `receiveCandidate.directionEvidenceSchema = 1`；`directionSamples` 最多 12 条，匹配母群回调应尽量有 receive/outgoing 的 before/after。
- 每个 before/after 只有数字/布尔值，包含 from/to/sender 读取状态及账号/母群关系；不得包含原始字段、正文、消息 ID 或异常文本。
- 若样本显示原方法前后关系不同，不得自动采用 before 数据放行；如果读取失败，应核对实际 getter，不能按会话参数猜发送者。
- 若仍是 waiting 且 offered 为 0，保持该事实，不伪报成功。若进入 preview，核对来源后仍只建立计划，不触发真实转发。
- 样本仅内存，重新等待清空，进程退出不保留；最多 12 次额外探测，超限有丢弃计数。300 条固定事件日志仍按 0.2.4 的规则持久化。

字段说明及维护策略见 `RUNTIME-DIAGNOSTICS.md`。本轮不开展 100/200 群发送。
