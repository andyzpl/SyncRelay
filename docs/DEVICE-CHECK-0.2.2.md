## 先测入口

1. 用 0.2.2 普通 DEB 替换旧插件，保留数据；完全结束微信进程后重新打开。首次悬浮开关仍默认关闭，已手动开启过的选择保持不变。
2. 进入「我 → 设置」，查看列表首组和底部，找「SyncRelay 转发」。优先为宿主原生行；若私有表适配失败，仅在设置列表底部保留同名恢复入口，不会强制出现窗口悬浮球。
3. 点入口后确认页内为 0.2.2，能看到分组设置、保存草稿、适配诊断与悬浮开关。关闭应回到微信设置，原有设置项照常使用。
4. 返回「我」再进入设置至少五次，打开/关闭插件页，切一次后台后回来；入口不得消失或重复。可再测试“打开微信后很快进设置”，验证异步初始化晚到的情况。
5. 查看/复制「适配诊断」，特别是 `settingsEntry.state`、`tableSource`、`tableClass`、`cellFactory`、`hooks`、`refreshCount`、`settingsFooterRecoveryActive` 与 `storageReady`；报告不应包含 wxid、群 ID 或消息正文。
6. 「开启悬浮入口」可选：开关打开后关闭面板才出现；关掉立即移除，重开保持选择。不要依靠它替代主设置入口验收。

若设置列表从头到底仍没有入口，请先发设置页截图、微信版本/构建号、注入工具和是否共存其他插件；若闪退，先停用 SyncRelay 并保留对应崩溃日志。未连接设备，不能保证本轮覆盖所有实际变体。

## 入口能进后再测群数

1. 母群选择页记录候选数，搜索几个上一版漏掉但本地会话存在的普通群；无需选择全部目标。
2. 复制完整脱敏诊断，确认 `groupRead` 的联系人/会话各来源状态和计数。仍只有 4 群也如实回传，不继续盲猜参数。
3. 可预览一条 100 或 200 群规则及不足额情况；生成、保存和预览均不发送。群池不写死 3000 上限，分批规则要求不变，不做大批量实发。

本轮需要：设置入口截图、0.2.2 页头截图、完整脱敏诊断、群候选数、微信版本/构建号。确认入口可靠后再安排单条接收与单个授权群的手动观察。
