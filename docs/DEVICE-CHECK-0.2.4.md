# 0.2.4 运行诊断与母群切换真机检查

日期：2026-10-21。真实转发仍未启用。目标为 iOS 16.0.3、微信 8.0.76 / 8.0.79，实际兼容性需设备验证。

## 安装与原生设置

1. 替换旧插件后完全结束微信再打开，从「我 → 设置 → SyncRelay 转发」进入。
2. 页面应为紧凑导航栏、灰底白色通栏分组，先显示来源设置，诊断位于末尾“更多设置”；版本在末尾应为 0.2.4。旧 0.2.3 包没有本轮改动。
3. 常规字号下左侧名称/右侧当前值，无障碍大字号上下排列；选择群或成员时仍显示完整原始 ID。检查小屏、深色、长群名及大字号，不能截掉关键身份信息。
4. 保存、关闭/放弃未保存修改、返回、开关、搜索全选和成员多选应保持原行为。原生样式尚未在实际 iPhone 上看过，不把语法检查当成视觉验收。

## 更换母群后等待

1. 先建一条规则并保存，记住目标数量；更换母群后目标规则不再全部清空。
2. 如果新母群原本在目标中，只移除该群；只有被移空的规则删除。来源成员需要重新选择，“我”的 wxid 仍可勾选。
3. 重新选来源成员并保存后再点击“等待源消息”。缺成员会具体提示，不能只显示笼统错误；没有目标规则也会明确要求先分组。
4. 确认开始等待，关闭插件面板回母群，由所选来源发普通文字，保持前台不锁屏。等待第一条具有服务器 ID 的匹配候选。
5. 有预览则核对正文、母群、wxid；确认只建立计划，不会向任何目标发消息。既有计划和历史不应被草稿变更改写。

## 抓不到时导出

1. 复现后先不要重启，回到插件 → 更多设置 → 导出运行诊断。
2. 分享/存储生成的 JSON，再把文件回传。也可在“运行诊断”页查看、复制及导出；分享面板实际可用性尚需本次验收。
3. 报告应有 `reportSchema = 1`、`build.plugin = 0.2.4`、具体编译提交和 CI run；不能一直显示 working-tree/local。
4. 报告应有 `draftSummary`、`sourceCapture`、`receiveCandidate.counters`、`runtimeLog.events`；不能包含你的真实 wxid、群名/群 ID、消息 ID或正文。
5. 回传时说明：更换母群前后、本人还是其他成员、是否保存、提示原文、大概操作时间。无需提供消息内容。
6. 若进后台/锁屏，等待应停止，日志有 `inactive`，回前台需手动重新开始；不要将按设计取消误认为源消息已被拒绝。

日志上限 300 条，可跨重启保留最近固定事件；当前回调计数在重启后重置，因此优先在失败当次导出。写盘有约一秒合并窗口，不能当作无损崩溃记录。

维护与原因码说明：`RUNTIME-DIAGNOSTICS.md`。手机尚未回传前，不能宣称“抓取不到”已定位或修复，也不放宽来源群/wxid 检查来制造成功。
