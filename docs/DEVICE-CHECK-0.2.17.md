# 0.2.17 小群规则与前台进度真机检查

适用：iOS 16.0.3，已观察微信 8.0.79.35。8.0.76 及其他环境仍需独立验证。本文件是待执行清单，不是测试已通过的报告。普通 DEB 的实际构建来源、大小及校验值以本次交付记录为准。

## 安装与准备

覆盖安装后完全退出并重开微信，确认设置页显示 0.2.17。本版本数据库会加表升级到 schema 7，保留配置/计划/历史/图片；不要降级回旧包。启动和恢复环境本身不会开始发送。

主入口仍是“我 → 设置 → SyncRelay 转发”。不用打开旧“单群文字/图片实验”开关，也不用先做接口检查。旧单群实验已经尝试过的源消息不能用于本轮规则，改用新发的一条消息。

## 第一轮：一条文字规则

1. 选择母群、本人或指定成员 wxid、文字类型，间隔可用 10–20 秒；手动只选 1–3 个有授权的测试群组成一条规则。母群和排除群不得出现在目标中。本轮不要直接使用 100/200 群大规则。
2. 保存，手动开始等待；回母群发一条新文字。返回预览，确认内容建立计划。这一步不发送。
3. 打开“已确认内容计划”，进入该计划，点规则 → “开始小群测试”，核对列出的目标后点“开始这条规则”。只需这一次开始，不逐群确认。
4. 关闭插件面板，在微信前台回复另一个聊天、打开视频号。观察进度胶囊是否出现、可拖动、不会挡住整页操作；输入时应避让键盘。视频播放/滚动和输入流畅度尚未实测。
5. 点胶囊“暂停”。如当前尝试在途，显示“在途处理中 / 等待”，收尾后再显示“继续”。暂停不撤回已提交消息。手动继续后等待一个新间隔，不能瞬间补发。
6. 结束后整体检查：实际测试群是否收到准确文字、数量是否正确、有没有重复或发到额外群。历史的“已提交”不等于已确认送达；胶囊“已处理”也包括结果未知。当前规则完成不自动开始下一条。

下一间隔从上一次结果处理后计时，且插件有有限的内部证据读取，因此实际两次发送间隔可能比设置上限更长。随机节拍不是平台许可或避开限制的保证；不测试无授权群，不急于扩大数量。

## 第二轮：静态图片

用新消息、新计划再测 1–3 个测试群，选择图片类型并确认真实预览。支持的是已加载的静态图片快照重新生成 JPEG，不承诺原图质量或动态图片。开始方式和文字相同，检查实际收到的图片内容、清晰度及数量；不是只看插件计数。

## 中断与恢复（另用新计划）

- 切后台或锁屏：应停止后续派发、隐藏胶囊并释放本插件常亮；回前台不自动继续。手动锁屏不受常亮设置阻止。
- 重新进入内容计划的规则菜单，选择“继续未尝试的群”；只发送 pending，不重发已提交、失败或未知的群。
- 强退重开也不自动开始；数据库保留进度和原生占位。中断时在途项记为结果未知，不能猜测没发出去然后重发。最后一项已处理时可能直接显示完成，但异常仍保留。
- 如不想继续，选择“结束这次执行（不重发）”，释放活动规则；下一条仍要手动开始。存在在途时结束也不能撤回消息。

## 前台体验核对

聊天键盘、视频号播放/全屏、浅深色、大字体、竖横屏分别留意胶囊文字/位置/点击。它仅挂在微信前台普通 key window，不创建系统悬浮窗口；宿主使用额外窗口的全屏场景还需核对。暂停或完成后常亮恢复原值，原来的可选悬浮入口偏好不改变。

有异常再导出一份诊断，反馈大致步骤、实际收到情况和出错时间即可；不要求每个群都截图或人工复核才能继续。诊断没有正文/账号原始 ID，不把手机原始报告上传公开仓库。当前未声称真机多群、视频不中断或所有目标必达。
