# SyncRelay 后续 UI 开发规格

日期：2026-11-10。状态：设计基线，待功能验收后开发；不是已实现功能或真机截图。

目标：首页只做导航，二级页分别管理来源、内容、目标和偏好；微信里继续聊天时，转发只占一个可收进屏幕边缘的小控件。

本规格以本轮讨论为准，更新旧方案中的页面结构、入口命名和胶囊收纳交互。不替代[阶段计划](OPERATIONS-CAPSULE-PLAN.md)、[状态与身份契约](OPERATIONS-V2-CONTRACTS.md)或[既有前台行为](FOREGROUND-PROGRESS.md)，不改变能力门禁。阶段 A 验收前不进入 B/C；每个发送入口只接已实现、已验收且当前账号/环境可用的能力。视频发送、消息库派发、主动图片链路不得因 UI 改版而提前开启。

## 1. 首页：四个纵向大入口

从「微信 → 我 → 设置 → SyncRelay 转发」进入。四行固定顺序，整行可点，左图标、中间标题和一行摘要、右箭头；行高可从 64–72 pt 起调，随系统大字号增长，不截断关键信息。用原生分组列表的浅灰背景和白色行，深色随宿主，沿用同一强调色；实色按钮留给二级页的主操作，不做四张彩色大卡片。

```text
SyncRelay
先设置母群                      ›  ← 可选提示，明确指向下一步

群同步                          ›
母群与消息来源 · 未设置
消息库转发                      ›
选择消息并转发
群分组                          ›
目标分组与排除群 · 未配置
设置                            ›
节奏、显示与诊断

转发记录                        ›  ← 独立的轻量入口
```

顶部只在有需要时显示一条可操作的提示，例如「先设置母群」「去群分组」「查看本次进度」。按实际任务给提示：母群未设不能阻断独立的库消息浏览或转发。无阻塞时不放固定提示条；不放长说明、实验入口、调试状态码或成套统计。计数不可读取时不显示为 0。

「转发记录」沿用原生圆角分组列表和推入／返回动效，按启动时间从新到旧混排群同步与消息库批次。每条显示冻结消息摘要、来源、开始时间、目标群数和结果；详情分为消息摘要、执行结果和逐群状态。只确认了计划、尚未创建执行批次的不显示。已提交不等于已确认送达，历史详情不提供开始、重发或继续操作。若历史只保存了群标识，按原记录展示，不根据当前分组推断旧群名。

## 2. 四个二级页

| 页面 | 首屏和主要操作 | 不放在这里 |
| --- | --- | --- |
| 群同步 | 母群、来源成员、受支持的消息类型、捕获状态。「保存」只保存配置；在手动捕获流程里，保存有效配置后才能点「等待一条新消息」，捕获后查看预览，再由用户决定下一步。 | 目标群编辑、直接发送、进入页面自动捕获。 |
| 消息库转发 | 库内消息列表，按「待转发 / 已转发 / 待核对」浏览。列表显示类型、摘要或缩略图、时间和必要状态；点开查看内容、选择本次分组、确认转发或查看历史。空库显示「消息库还没有消息」；只引导到已验收的入库方式。 | 选中消息即发送、自动接下一条、手动发送实验。 |
| 群分组 | 默认「目标分组」，可切「排除的群」。列表显示组名和实际群数；点开查看/编辑群名单。顶部区分已分组、未分组和排除数，未分组可点进处理。提供「自动生成分组」预览，明确点「保存分组」才生效。 | 保存时自动发送、把未分组算作排除、把分组规格写成实发上限。 |
| 设置 | 全局转发间隔、已支持的显示偏好、维护与关于。「诊断」页内提供只读查看和主动导出；版本放「关于」。已验收的消息库容量/资源管理可作为独立入口，不在首屏堆资源明细。 | 母群、分组名单、发送记录；正式版不展示单群文字实验、图片实验、手动观察、接口检查、内部状态码或重复调试入口。 |

- **两条来源独立。** 群同步只处理符合已保存母群/成员/类型条件的新消息；消息库只展示当前账号明确保存的条目。捕获或预览不会自动入库，也不会自动发送。群同步预览的「保存到消息库」只有对应能力验收后才接入；已有获准的捕获策略也不能由页面打开或回前台触发。
- **“已转发”不等于送达。** 列表投影既有任务结果，不另建 UI 状态表。未结束任务在消息详情显示进度及允许的操作；有未知结果时进入「待核对」。只失败、未发或取消的记录不能假标为「已转发」，仍可在详情查阅。记录页以本次消息、分组和批次为单位，显示完整日期和时间。
- **分组不是授权发给所有群。** 母群自动排除；人工排除、未分组、已分组互不混用。统计来自同一份已核对的群池，不能把微信本地候选群数称为已加入群总数。先预览新分组和影响范围，不静默补位、重排旧组或重写已有计划和历史；人工排除对在途/未发项的影响遵循已验收的 Core 契约。
- **配置只维护一份。** 每组群数放在「群分组 → 自动生成分组」中；如设置里需要入口，只跳到同一配置，不复制一份。概念图里的 100/200 群和 5–10 秒是分组/节奏示例，正式值由已保存配置及能力上限决定。保留必要的脱敏诊断和底层测试，不把清理日常入口等同于删除测试或历史数据。

## 3. 发送前：确认和补分组

**正常路径**：消息库 → 点一条消息 → 预览正文/图片 →「选择分组转发」→ 选定本次分组 → 确认 → 明确点「开始转发」。群同步的已核对内容复用相同的选组、确认和运行页面，不要求用户先学会创建 plan/run。

- 确认页展示本次消息、所选分组、实际目标群数和转发间隔。说明本次只执行用户确认的范围，不自动接下一组或下一条，不自动重发未知结果。若已验收的能力只允许一次执行一组，选择器只做单选；其他组数只作概览。超过实发限制时说明原因，不偷偷截取。
- **没有可用分组**：点转发时提示「还没有可用的目标分组」，提供「去群分组 / 取消」；仍可浏览原消息。若本次拟覆盖范围有未分组群，列出未处理数量，让用户分配、明确排除或重选本次范围，不能默默漏掉，也不强制将账号所有群入组。
- **保存后回到原消息**：保留当前账号和原消息/内容版本身份，返回详情重新读取并核对目标；提示「请选择本次分组」，不自动发。若账号变了、原消息已不可用、所选版本有变化或存在另一个占用任务，清掉旧确认并说明原因。不能把操作转给当前列表第一条或另一个任务。
- 能力未开放、素材无效、读取失败与「没分组」分开提示。能力关闭不显示可执行的发送按钮，不用跳群分组掩盖真正的不可用原因；未知类型不降级成文字。

## 4. 悬浮胶囊：往外推收纳，点一下拉回

2026-11-11 实机反馈修订：空闲快捷入口改回写「同步」的短胶囊，替代此前 S 圆钮要求。点击仍只打开四入口首页，不发送。活动、暂停、结束及主动收纳规则保持不变；旧参考提示词中的 S 圆钮段落不再是空闲形态的实现依据。

**默认形态是小胶囊，不是圆球，也不是默认贴边的长条。** 活动任务首次出现时显示小胶囊，默认右下安全区、避开输入框。显示「转发中 · 已处理 12/20」及「暂停」；点胶囊主体才看详情，主按钮直接操作该批次。可把胶囊拖到左右侧及合适高度。可选的空闲快捷入口如获准开放，复用同一个控件，默认不额外挂第二个悬浮球。

```text
正常小胶囊                      往外推松手                 点一下或向内拖
[转发中 · 已处理 12/20 | 暂停]  ─────────→  右边缘竖条  ───────────→  小胶囊

右边缘竖条：                     镜像到左边缘时箭头朝右：
╭────┐                           ┌────╮
│ ‹  │                           │  › │
│ 转 │                           │ 转 │
│ 发 │                           │ 发 │
│ 中 │                           │ 中 │
╰────┘                           ╰────╯
```

- **主动向外推才收纳。** 正常拖到边缘只停靠，仍显示完整胶囊。继续向外推超过收纳阈值、松手后才短促吸附到同侧竖条；拖回或未达阈值不收纳。不用空闲计时自动收起。点整条或从控件上向内拖，从原侧滑回小胶囊，不直接弹大面板。
- **右侧箭头朝左，左侧朝右。** 箭头在上，中文一字一行保持正立，不旋转文字。固定留足三字高度，切状态不改尺寸、不跳位置；只留状态文案，不塞数字或暂停/继续按钮。整条提供足够的触摸面积（目标至少 44 pt），同时不通过透明全屏区域抢触摸或拦截微信返回手势。
- **收纳和运行完全独立。** 转发中也能往外推，贴边写「转 / 发 / 中」，队列按既有前台规则继续。暂停、收尾、完成只更新当前位置的文案，不把胶囊突然展开。点竖条、挪位置、打开详情或关闭结果摘要都不会开始、继续、暂停或结束发送。
- **展开是主动操作。** 点胶囊主体，沿原侧展开简短面板，显示本次进度、结果分类和「查看详情」；不模糊/盖住整个微信。运行面板可暂停，暂停面板可继续未尝试目标，不能撤回已提交项；「结束本次」仅在已支持时提供，明确确认后执行。关闭面板只关闭 UI。
- **结束后能找到记录。** 小胶囊简化为「本次执行结束」，可查看记录或关闭；若原来在边缘，原位显示「已结束」，不自动弹出。关闭摘要不删历史，也不启动下一条；没有活动任务且未开启快捷入口时可隐藏。

| 任务状态 | 贴边竖排文案 | 小胶囊/展开面板 |
| --- | --- | --- |
| 空闲（可选快捷入口） | 不收纳为任务把手 | 「同步」短胶囊，打开对应入口，无发送动作。 |
| 运行 | 转发中 | 已处理/总数；暂停。 |
| 暂停后的在途收尾 | 收尾中 | 「在途处理中」；暂不能继续。 |
| 已暂停 / 回前台待手动继续 | 已暂停 | 原因按实际状态显示；身份和能力核对后仅继续未尝试目标。 |
| 执行结束 | 已结束 | 查看转发记录 / 关闭；详情区分完成、取消及异常。 |

进度口径由 Core 提供。胶囊里的「已处理」不是「已提交」或「已送达」；详情分开显示已提交、已确认送达（仅在有可靠证据时）、失败、结果待核对、未发、在途和已取消。不把不同口径当作可相加的总数，也不用示意图里的数字推算送达率。

### 手势与宿主边界

- 拖动跟手，松手吸附和从同侧展开用短动画；进度只在值变化时更新，不呼吸、不闪烁、不滚动数字。开启系统「减少动态效果」时改为短淡入或直接切换。
- 只在微信前台有效的宿主视图内显示，不创建抢焦点窗口，不做跨 App 悬浮；键盘、横屏、返回手势、视频全屏和小窗口下重新限制位置，空间不足暂时隐藏。插件内页有完整进度时不叠在保存、返回或输入控件上。胶囊之外继续由微信处理触摸。
- 切后台或锁屏遵循既有停止新派发/收尾规则；回前台只投影已核对状态，不自动捕获或继续。账号无法核对或发生切换时，隐藏旧摘要、旧进度及旧操作。浮层不展示群名、账号、正文、文件路径或素材 token。

## 5. 开发顺序与验收

1. **先确认门槛。** 记录当前阶段验收、目标构建/宿主和对应真机证据，列出各入口可接的能力；未通过的保持关闭。此文档不构成构建、安装、迁移、设备清理或派发授权。
2. **改页面骨架。** 保留微信原入口和已有恢复入口；在 `UI/` 内拆出首页、四个二级页和确认/回跳流程，优先复用 `SRPanel`、`SRPlanScreens` 及现有原生列表样式。验收后再移除正式 UI 的旧实验入口，确认设置和诊断仍能进入。
3. **接唯一状态与悬浮。** 由 `SRFloatingProgress` 负责显示、拖动、停靠和操作事件。位置/形态属于 UI，业务状态只取 Core；开始、暂停、继续、结束使用稳定 coordinator/API 和用户点击时绑定的账号、内容/版本、plan/task、run、generation、确认键等适用身份。双击和迟到操作不得开第二个任务或触发重发。此次 UI 改版不要求新增 schema、宿主 ABI 或并行状态源。
4. **测试再交付。** 加入聚焦测试并尽可能运行完整本地测试；Objective-C 行为走原生模拟，若另有获准的状态机变更则补 C 测试。分别记录 Python 契约、C 状态、macOS 原生模拟、生产构建/包及真机证据，不相互替代。

真机 UI 验收至少覆盖：

- [ ] 首页四行、二级页返回、浅/深色、大字号、VoiceOver；来源未设、空库、读取失败、能力未开放的提示各自正确。
- [ ] 无分组跳转、保存回原消息、取消不发、确认目标数一致；账号变化、内容版本变化、双击/旧确认均不误发。
- [ ] 转发中可拖、可在两侧主动收纳，普通停靠不误收；竖排「转发中」可读，点/拉回只恢复胶囊；暂停、收尾、结束只在原位更新。
- [ ] 键盘弹出、横屏、聊天回复、视频号/全屏和微信返回手势不被浮层抢占；锁屏/切后台后无自动继续，未知结果不自动重发。
- [ ] 记录计数与实际任务一致，诊断由用户主动开启/导出并脱敏；旧测试入口移除后，正式入口与维护功能仍可达。
