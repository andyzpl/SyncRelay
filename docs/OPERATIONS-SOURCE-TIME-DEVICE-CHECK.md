## 已实现的文字采样边界

- 新 `Adapter/SRSourceTimeProbe` 由 SREntry 长期持有，复用唯一的 SRWeChatReceiver 及原始 receive/outgoing hook 链，不另建 receiver 或 swizzle。关页面不停止本轮；定时检查复用全局 entry 的现有定时器，不依赖设置页存活。
- 默认关闭，用户明确开始/停止；一轮最多 **16 个已交付文字回调或 120 秒**（单调时钟计时）。到限停止，不自动重开。后台/锁屏停止，账号不可核对/变化或配置变化停止；账号/配置失效还清空本轮证据，已停止的报告也不会跨账号展示。开始新轮会替换旧样本，退出进程不保留，需先手动导出需要保留的报告。
- 开始时核对稳定账号、已保存配置及来源成员，并要求文字类型已保存。采样 arm 的冻结副本只选择 `text`，不改写保存的类型配置。因此图片在 receiver 的类型过滤处就被拒绝，**不会为采样调用 prepareImage、下载资源或保存图片快照**。原手动图片链路及并行类型适配保持不变。
- 与等待/预览、小群执行、旧单群实验、倒计时、发送观察及图片接口检查互斥；晚确认和发送端口也检查采样状态。采样回调只记脱敏证据，不进入 `offerEnvelope`，不建立内容/计划/run/claim，不调用发送。停止后既有手动捕获继续走原回调，旧 receiver 代次不能混入新轮或手动捕获。
- 不修改 schema、20 群上限、发送核心或协调器的来源认证输入。样本的 `strictPolicyWouldAccept` 只是**假设宿主整数确为 epoch 秒时**的本地保守策略结果，不能作为真实单位/语义认证，更不能自动设置 `sourceTimeVerified=true`。

### 报告字段与解读

运行诊断新增 `sourceTimeProbe`。报告只在用户主动导出时写入临时诊断文件，不自动上传；采样模块本身不写文件或数据库。

| 字段 | 含义与限制 |
| --- | --- |
| `state` / `round` / `active` | 固定状态码、本进程本地轮次、是否仍采样；切后台回来不自动续开 |
| `getterDeclaredReturnEncoding` | 配置的 CMessageWrap 类上声明的整型返回编码，或固定 `missing` / `incompatible`；不是反射猜测后强行调用 |
| `getterDeclarationScope` / `actualWrapABIObserved` | 固定为 `configured_wrap_class` / `false`；没有实际消息对象的逐对象返回编码证据，不能声称该项已实测完成 |
| `ordinal` / `messageOrdinal` / `receiverGeneration` | 回调顺序、同轮消息的匿名关联序号、原 receiver 代次；重复同 ID 回调可共用匿名序号，不导出原始消息 ID |
| `createdAt` | receiver 在原方法调用前按声明 ABI 读取的整数原值，不自行换算秒/毫秒；不可读取、非正或超出 JSON 精确整数范围的值记为 null，不伪造替代时间 |
| `receivedAt` / `listeningSince` | 原方法调用前首次观察时间 / 该次 receiver arm 的边界；沿用原证据，不改为主队列执行或本人服务器 ID 就绪时间 |
| `deliveredAt` / `deliveryClockRollback` | 采样消费回调的本地时间及相对首回调的回拨标记；只用于比较延迟，不替代前三个时间 |
| `selfSource` / `relationship` | 是否选中本人、固定时间关系码；`future_or_different_units` 既可能是未来值也可能单位不同，不能自行下结论 |
| `sourceTimeSemanticsVerified` / `imageReadinessObserved` / `prefilteredCallbacksObserved` | 均固定 false；样本出现和本地策略通过都不会翻转这些能力位 |

报告不包含正文/XML、账号/群/成员/消息原始 ID、素材路径或凭据。同消息匿名序号的原 ID 对照只在本轮有界内存中，停止即丢弃；它**不是** C 阶段的持久目标级去重账本。

### 本入口不能覆盖的项目

1. 图片及资源就绪、图片晚回调：本轮有意在类型过滤处排除，不能用空样本记通过；需要后续与接收适配并行工作协调一个不会触发资源写入的证据 seam。
2. 只有 CMessageWrap 配置类的 ABI 声明，没有实际 wrap 子类的逐对象声明；这一缺口保持显式 `actualWrapABIObserved=false`。
3. 没有服务器消息 ID、空文字、错误来源/类型/方向等被 receiver 提前拒绝的回调不进入本入口。这里不是完整 hook 原始事件流；离线同步没有可交付回调时只记证据不足。
4. 本机/CI 的模拟对象通过不能代表 8.0.76 或 8.0.79 的真实宿主已验证；两个版本仍分别登记，不能外推。

| 前台本人文字 | 同样手动发合成文字，允许等待服务器 ID 可用 | 最终证据沿用首次回调，不能把服务器 ID 就绪时间当创建时间 | 仅最终已交付文字；无服务器 ID 的事件不可见 |
| 离线补同步 | 断网期间由选定成员发文字；本机开始采样后保持微信前台再恢复网络 | 回调可晚到，创建时间仍指向离线时的旧消息，不能被识别为新消息 | 仅可交付文字；控制中心中断轮次或没有回调均不能记通过 |
| 历史重新出现/重复回调 | 在可复现的历史加载或同条同步场景观察重复回调 | 不因到达时间变晚而刷新创建时间；不向内容或发送账本新增记录 | 仅同轮文字的匿名关联；不是持久目标级去重验收 |
| 前后台后补同步 | 后台/停止采样期间产生消息，回来后新开一轮并观察补同步 | 旧消息不能跨新的监听边界被误认；没有回调则记录未覆盖 | 可能在新开轮前已同步；无样本记证据不足 |
| 静态图片延迟 | 对他人和本人图片分别记录首次回调及可用的后续资源就绪观察 | 创建/首回调证据不变；仅准备完成的晚时间不能使旧图片变新 | 未覆盖，不用空样本记通过 |
| 同秒边界 | 若自然捕捉到监听与创建同秒，记录该样本 | 生产严格策略保守拒绝；手工未复现时只引用模拟结果，不补造真机结论 | 仅自然出现的文字样本；不修改系统时间 |
| 停止重开/旧代次 | 本轮停止后重开，等待旧图片或旧本人回调 | 原轮样本不能被重标为新一轮消息；不开始发送 | 仅旧本人文字可能可见；图片未覆盖 |
| 配置/账号身份 | 测试配置改变或实际账号不可核对时的停止结果 | 原来源样本失效，不展示旧账号内容；无法安全执行账号场景时记未覆盖 | 原报告失效会清空；先导出，不强求切换实际账号 |

离线、后台与图片资源场景若平台不产生可观察回调，必须写明能力边界，不能把“没看到”推断为新旧判据正确。

## 验收与结果填写

至少有可关联的实时、离线补同步及图片/本人延迟证据，才能判断当前支持版本是否具备可信的来源时间方案。若时间实际表达的是入库/同步时间，或单位/语义仍有歧义，维持来源待核对，不开放自动捕获。

结果逐项填写：实际版本/构建、场景、本轮序号、用户操作先后、观测时间关系、通过/失败/证据不足及原因。对外记录只保留脱敏结论，不把原始诊断上传公开仓库。验证结论由工程核对后更新，不让 UI 开关或单个 getter 布尔值自行认证。

当前结果：**全部真机场景待测，未收到本包的安装或采样反馈。** 第一批反馈只需 iOS/微信/插件版本及构建、场景与操作顺序、`sourceTimeProbe` 脱敏字段、是否出现意外捕获/发送；不需要提供原始 wxid、群名、正文或账号凭据。暂时不能做离线/图片/ABI 项时明确注明，不把两轮实时文字通过扩大为整阶段通过。
