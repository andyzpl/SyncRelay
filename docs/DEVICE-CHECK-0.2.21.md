# 0.2.21 消息类型探针真机步骤

本轮只采集数字类型和顺序，不发送任何消息。请使用 `dist/0.2.21-test-39698033364/andyz.syncrelay_0.2.21_iphoneos-arm.deb`，不要把 0.2.20 包改名安装。

## 准备

1. 覆盖安装 DEB，完全退出并重新打开微信。在“我 → 设置 → SyncRelay 转发”确认显示 `0.2.21`。
2. 打开已有配置，核对母群、同一个实际发送者 wxid 和测试群；保留至少一个有效规则以满足现有配置校验。不要点击“开始小群测试”或任何发送实验。
3. 为了让最后的普通文字结束等待，只勾选“转发文字”，暂时不要勾选图片。自带表情按当前设备表现属于类型 1 文字；本轮不需要发送它，避免它提前生成文字预览并停止等待。

## 采样顺序

1. 点击“等待源消息”，再回到同一个母群。
2. 由同一个已选来源成员，按下面顺序各发送一条新的消息；每条之间等到消息在群内显示后再发下一条：

   `语音 → 名片 → 自定义表情 → 视频 → 文件 → 链接 → 普通文字`

3. 文件和链接在微信 8.0.79 都是类型 `49`，可能出现一次以上回调；这是回调计数，不是去重后的消息数。不要用历史转发、撤回重发或其他成员的消息替代。
4. 普通文字到达并出现预览后，返回插件，放弃这条预览（不要确认计划或发送）。打开“适配诊断”并导出报告。

## 报告核对

查看 `receiveCandidate.messageTypeProbe`：

- `sequence` 应按本次回调顺序出现，典型结果类似 `[34,42,47,43,49,49,1]`；文件/链接回调次数可不同。
- `rows` 是按数字去重的计数；34、42、47、49 行应分别带 `observedRoute`，43 行故意没有该字段。
- `directionSamples` 至少应能看到 `fromIsSource=true`、`fromIsGroup=true`、`toIsAccount=true`。
- `build.plugin`、`pluginVersion` 必须是 `0.2.21`。如果仍是 `0.2.20`，先停止，不要用该报告判断新包。

只要数字和方向正确，本轮探针就完成。报告不会包含正文、XML、文件路径、音视频数据或账号/群 ID；未知类型仍会显示 `receive_type_filtered`，这是预期行为，不是捕获失败。
