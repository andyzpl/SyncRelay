# 一次手动文字发送的只读观察

日期：2026-10-20。源码：`Adapter/SRWeChatSendProbe.h/.m`。当前没有主动发送功能，微信 8.0.76 / 8.0.79 均未真机验证。

## 为什么先观察

原 MikotoHelper 的一个文字路径已定位到 `MMContext -> CMessageMgr -> AddMsg:MsgWrap:`，但调用完成、本地消息 ID、服务器 ID 或单独的状态码都不能直接当作可靠送达证明。原包分析的准确地址及边界见 `MIKOTO-SEND-EVIDENCE.md`。

这一工具用于对照用户在微信原界面的正常手动发送，核对候选接口与消息关联。它不是 `SRRunner` 的发送器，不写计划、运行批次或投递结果，也不调用原插件方法。无法观测不等于发送失败；能够观测不等于兼容全部转发路径。

## 操作范围

1. 用户点击“适配状态”中的“只读观察一次手动文字发送”，从可搜索列表选择一个授权测试群并确认。
2. 主线程核对当前账号和版本，检查 `CMessageMgr AddMsg:MsgWrap:` 为 `void(object, object)`，以及 `CMessageWrap` 的必要字符串/整数 getter ABI。
3. 仅通过检查后安装观察 wrapper，最长 120 秒。启动插件不会自动安装；不能和母群源消息等待同时开启。
4. 关闭面板，回所选群手动发送一条普通文字；请停用其他自动发送功能，不要在该窗口连发多条。
5. 再打开面板，停止观察后进入“查看适配诊断”并复制报告；过期或失去活跃状态也会停止，不需为本观察开启防锁屏。

全部命中条件是：会话参数等于所选群、from 等于当前账号、to 等于所选群、type 为整数 1。只观察第一条匹配消息的元数据；后续匹配只累加计数，不替换第一条消息的读取键。不按正文、昵称、最近一条消息或哈希猜测关联。

## 保留原发送链

- wrapper 先原样调用原实现；原参数不修改，原实现的异常不被附加观察吞掉。
- 每个管理器类只安装一层本项目 wrapper，同一类同时只有一个监听器；继承来的实现先以子类方法隔离，不覆盖父类方法。
- 停止只移除监听器并使排队代次失效，不贸然拆除其他插件可能串接的方法链。wrapper 保留到进程退出，无监听时只调用原实现。
- hook 部分不获取账号或读消息历史，只读匹配消息的必要标量/字符串元数据，随后交付主队列；主队列再次核对账号、时钟、期限与代次。
- 与其他插件的 hook 顺序、真实回调线程、arm64e 和 getter 安全性仍须设备核对；ABI 匹配不是这些行为的兼容证明。

## 精确读取及未知状态

观察到的 local/server ID 保留为精确整数，不经过 double，不截断超过 2^53 的值。未分配的 0 不当成有效关联键。

主线程每秒尝试观察，最长到本轮期限：

- 已获得非零 local ID，且 `GetMsg:LocalID:` 为安全的 `object(object, integer)` ABI 时，只用所选群及该精确 local ID 读取。整数无法装进实际参数宽度时不调用，不截断。
- 返回对象必须再次匹配 from、to、type 和精确 local ID，否则只增加读取未匹配计数，不改为查询其他消息。
- 尚无 local ID，或没有兼容的读取接口时，只能采样仍存活的原始弱引用 wrap；不强留原生消息对象。如果后来分配了 local ID，下一次才用该键读取。
- `m_uiStatus` 仅以原始整数保留，缺失/不兼容为 null。服务器 ID 冲突只记为身份冲突，不据此认定成功或失败。
- 不 hook `MessageReturn:MessageInfo:Event:`，不为其 event 或 status 填入未经验证的结果含义。

候选接口、读取线程和原始状态变化仍须在两版手机分别对照。即使手机显示发送成功，当前报告的 `deliveryOutcome` 也始终是 `not_determined`，不会写入“已确认”。

## 生命周期、上限及隐私

- 最多 16 个待交付回调、32 个脱敏样本；相邻重复样本合并，超额记录丢弃数，不无限增长。
- 使用单调时钟；停止、期限到达、失去前台活跃状态、账号不符或时钟无效时取消定时器、清除账号/群/消息 ID 与原生弱引用，并使旧代次回调失效。
- 观察中的账号变化会额外清空样本和计数；回前台、重启、切账号后都不自动开启。结束报告仅在内存保留，进程退出后不保证可取。
- 不读取 `m_nsContent`，不持久化消息体、凭据、原生对象或群名单。共享诊断只含方法编码、固定状态、计数、ID 存在/冲突布尔值及原始状态码，不含 wxid、群 ID、消息 ID 或昵称。

诊断位于原报告的 `manualSendObservation`：

| 字段 | 含义 |
| --- | --- |
| `observerOnly=true`、`sendingEnabled=false` | 仅观察，不发消息 |
| `deliveryOutcome=not_determined` | 永不以本报告认定送达 |
| `armed`、`installed`、`state` | 正在观察、曾安装 wrapper、本轮状态 |
| `observedOutgoing` | 本窗口内通过匹配并交付主队列的 outgoing 次数，不是成功数 |
| `lookupMisses` | 精确本地读取未匹配次数，不是发送失败数 |
| `identityConflicts` | local/server ID 冲突次数，不是错误状态枚举 |
| `droppedSamplesOrCallbacks` | 样本或队列超过上限后的丢弃计数 |
| `samples` | `after_add` / `live_wrap` / `local_readback`、ID 存在/冲突、原始 `statusCode` |

`state` 可为 `idle`、`waiting`、`observing`、`stopped`、`inactive`、`expired`、`account_changed`、`invalid_clock`。`installed=true` 不表示仍在观察或正在发送。

## 自动化验证与设备检查点

`tests/send_probe_test.m` 直接测试生产观察器，覆盖：版本/签名/主线程门禁、原链和异常保留、继承 hook、群/账号/类型筛选、后台回调到主线程、精确大整数与参数溢出拒绝、错群/错 ID 不关联、后发消息不替换首条、32/16 上限、停止/重新开启旧代次失效、账号/前后台/期限取消及诊断脱敏。模拟正文 getter 触发即中止，以防任何观察路径读取正文。

后台用例采用真正异步的工作队列并断言非主线程；不能用 `dispatch_sync(globalQueue, ...)` 假定一定换线程，它可能在调用线程内联执行。

这些是模拟对象测试，不是微信发送测试。第一轮手机只需一个授权测试群、一条由用户正常发送的文字；先核对入口和只读数据，再做接收与发送观察。没有 100/200 群实发入口，暂不做大规模或长时发送试验。操作和回传项见 `DEVICE-CHECK-0.2.0.md`。
