# 0.2.11 消息构造器 ABI 修正真机检查

## 修正依据

888 手机报告来自 0.2.10、iOS 16.0.3、微信 8.0.79.35。来源已进入单条预览，但 `initWithMsgType:` 的真实编码是 `@24@0:8q16`（64 位有符号整数），旧候选只接受 `i/I`（32 位），因此报 `initializer_abi_incompatible`。

该次 `submissionAttempted = false`、`deliveryOutcome = not_submitted`，持久实验 `claimed = false`，未进入倒计时、未调用发送接口，也没有消耗源消息实验占位。这不是群设置错误或平台风控的证据。

0.2.11 分别使用 `i/I/q/Q` 的准确参数类型调用构造器，保留 init-family 的 ARC 所有权规则；浮点数、对象、缺失或未知签名仍阻断。新增 `initializerArgumentType` / `initializerCallType`，分别记录已验证类型和实际调用类型；不包含账号或正文。其他账号、来源、目标、版本、防重复和常亮规则保持不变。

## 安装与单群检查

1. 完全退出微信，安装 0.2.11 普通 DEB，再按现有注入流程重载微信。原配置保留，不清数据库、不卸载重置；数据库仍为 v4。
2. 进入「我 → 设置 → SyncRelay 转发」，核对母群、来源 wxid 和一个授权目标测试群。只启用文字并保存；修改配置后不要沿用旧预览。
3. 手动等待并在母群发一条新的短文字，核对预览，先不要确认建立内容计划。
4. 在更多设置开启“单群文字实验发送”，点“单群文字发送（实验）”，只选一个授权目标，再二次确认。
5. 保持微信前台，等待至少 10 秒，然后最多观察 30 秒。预期不再因已观察到的 `q` 构造器类型被拒绝，但后续字段构造或调用结果仍需本轮设备验证。
6. 到目标群人工核对是否收到、是否只有一条、正文是否正确。无论结果如何，立即导出运行诊断并说明现象；不确定时不补发、不换第二个群继续试。

## 报告检查点

- 微信 8.0.79.35 的预期类型为 `initializerArgumentType = q`；进入构造后 `initializerCallType = q`，不能据此判定送达。
- 如果仍在门禁阻断，保留页面错误和 JSON；所有构造用 getter 也列入 `singleTextSendCandidate.methods`，不必提供真实 wxid 或正文。
- 本进程最多一次主机调用；调用前持久占位，同源跨重启不重试。停止观察不能撤回已提交的消息。
- 批量规则、100/200 群实发、图片、自动接力和自动重试继续关闭。人工确认、常亮恢复、锁屏/失活取消仍需验收。

包的确切源码、CI run、SHA-256 和本地核验记录写入交付目录的 `ci-provenance.json`、`SHA256SUMS` 和 `local-verification.json`；编译成功不等于真机送达成功。
