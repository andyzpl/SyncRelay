# 微信前台使用与进度悬浮控件

日期：2026-10-21。新增用户要求：转发时能正常回复其他消息、看视频号，不必留在插件设置页；前台显示进度并可直接暂停。

## 设计决定

- 北极星：聊天和视频仍是主角，转发只占一个可移动的小控件。
- 沿用既有微信原生方向，不重新探索品牌风格：系统中文字体、等宽进度数字、原有不透明浅/深表面及微信绿操作色。采用短胶囊而非塞满文字的小圆球，让暂停按钮保有触摸面积。
- 仅保留已处理/总数、当前状态、暂停/继续；不展示群名、账号、正文或逐群成功列表。“已处理”包括结果未知，不等于已送达。
- 运行：直接暂停；暂停但有在途尝试：显示“在途处理中 / 等待”，暂不提供继续；在途收尾后可手动继续，继续先等待新间隔。
- 控件出现采用 180 ms 淡入；系统按钮原生按下反馈；拖动结束 180 ms 吸边。遵循“减少动态效果”，不做循环动画、不让状态数字滚动打扰视频。
- 安全区内拖动、左右吸边，键盘出现时向键盘上方限制范围；过于狭小的可用区域暂时隐藏。进入/退出小群任务不修改用户的可选悬浮入口设置。

## 实现与生命周期

- 单独的 `SRFloatingProgress` 是宿主前台普通 key window 的有界子视图，不创建窗口、不调用 makeKeyAndVisible、不覆盖全屏触摸处理、不改变微信的聊天/视频控制器。
- 状态读取、UIKit 和实际消息 API 在主线程；runner 的私有队列仅异步提交主线程任务，不等待主线程。前台状态允许时，切换聊天、聊天输入和视频号页面本身不暂停队列。
- 微信失去 active、锁屏或账号无法核对时停止新派发并结束有限观察，不因返回前台自动继续。窗口切换时只移动控件，不触发发送。
- 新增的进度控件是执行期间的控制工具，不是原来可选、默认关闭的插件入口。任务完成移除，原入口偏好不变。
- 暂停不能撤回已提交的消息；“等待”用于在途收尾，不允许在上一尝试尚未落账时再次继续。

## 验证边界

本地没有连接 iPhone、UIKit 模拟器或当前微信截图，不能取得真实基线/新画面或完成独立视觉评审；不打视觉分，不把源码/语法通过当成画面及交互已通过。

本轮先以原生聚合模型和生命周期模拟检查运行/暂停/收尾/继续、总数/已处理数、账号可见性及新间隔。UIKit 通过双架构语法及 DEB 编译检查后，在真机依次验证：聊天回复及键盘、视频号滚动/播放/全屏、浮层拖动/吸边/暂停/继续、浅深色及大字体、切后台隐藏与返回不自动继续。

视频号可能涉及额外窗口、全屏与宿主自身播放策略；图片编码也可能占用主线程时间。尚未实测的播放连续性、输入顺畅程度、控件覆盖和设备资源竞争必须如实记录，不能据此承诺绝不掉帧或绝不中断播放。
