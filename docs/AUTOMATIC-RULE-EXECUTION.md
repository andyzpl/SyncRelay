运营胶囊与自动捕获的新开发基线见 `docs/OPERATIONS-CAPSULE-PLAN.md`。胶囊常驻、总开关、前台自动恢复捕获及完整状态联动以该独立计划为准；下文冲突内容保留作旧阶段记录，发送仍不得自动恢复。

## 当前开发顺序：先跑稳，再整理操作流程

0.2.20 检查点：每条 1–20 群真实执行已编译交付，新增文字/图片 20 群及暂停重启模拟回归通过，用户已反馈本轮测试全部成功、无失败（精确群数及新诊断未提供）。自动捕获和胶囊第二版仍未实现，本包不改变源消息获取流程。以下阶段提案不表示这些功能已经交付。

用户进一步明确：先把现有功能和少量群的实际转发测正常，稳定后再改使用方式。下文“用户流程”是正式使用目标，不是本阶段先重做界面的要求。

### 自动化与万能胶囊的阶段边界

- 这里的“自动化”首先指**自动捕获**：保存有效规则并开启独立开关后，插件在微信前台监听母群；匹配来源 wxid 和类型的第一条消息自动冻结为待确认预览，用户不再需要每次点击“开始等待”。自动捕获只找消息，不建立规则、不发送。
- 自动捕获默认关闭，且只在母群、来源 wxid、类型、间隔和目标规则均已保存后允许开启。切后台、锁屏、账号变化、规则修改或已有预览时停止监听；回前台不偷偷恢复。捕获一条后立即停止监听，防止连续消息覆盖源消息。
- 已有基础：自动按规则分组、一次点击启动当前规则后内部串行处理、暂停/继续、pending-only 恢复，以及不依赖设置页的前台进度胶囊第一版。
- 下一步先把真实规则上限从当前 1–3 个授权群扩到 10–20 个群，并实现上述自动捕获生命周期保护，完成文字/图片、暂停、重启和异常汇总回归。胶囊第二版（当前规则、批次进度、失败/未知摘要、继续按钮和完成时间）可以并行开发，但随小规模回归通过后再打包。
- 自动接下一条规则、后台持续发送、失败自动重试和无人确认自动启动不属于当前自动化范围；明确结果未知时必须停住，不能用自动化放大重复发送。

1. 先实现自动捕获开关和生命周期保护，再保留已成功的单群文字、静态图片基线及现有测试入口，优先接通小规模真实串行转发，建议先用 3 个授权测试群。一次启动后自动处理这些群，不逐群弹窗。
2. 在同一小规模范围验证文字和图片、来源人 wxid 过滤、母群/排除群保护、实际发送间隔、暂停/继续、切后台停止、重启后手动只继续未尝试目标；确认没有串群、漏掉进度或重复派发。开发验收可以查看实际结果，失败时再导出诊断，不把它变成正式使用步骤。
3. 用多次小规模测试的实际收到数、失败/未知数及重复情况判断稳定性。不从单次成功或方法返回计算虚假的“成功率”，也不承诺随机间隔能规避平台限制。
4. 小规模流程稳定后，再整理统一设置、自动分组和开始/暂停/继续的正式交互；根据真机结果分阶段扩到更多群，最终再验证每条 100/200 群的使用建议。群池大小不设 3000 的写死上限，不等于本阶段开放整个群池发送。

下一包的前置条件是：受限的真实 transport、生命周期和最小测试入口已接通且回归测试通过，普通 DEB 构建和下载后核验通过。不会只因为核心测试通过就交付一个仍没有多群执行链路的“多群测试包”。当前不需要用户反复用 0.2.16 验证它尚未实现的功能。

## 用户流程

### 后续交互提案（2026-10-21，尚未实现）

用户补充的胶囊流程作为后续产品设计方向：总开关仅在完整有效规则已保存后开放；捕获到符合来源条件的消息后提示用户，点击转发再展示分组选择列表。每组展示今日进度（如“第 2 组 · 100 个群 · 今日已发送 34 / 100”），未完成可选继续或重新发送；完成显示真实完成时间，再次发送必须二次确认。进度胶囊只负责轻量提示和暂停/继续，不自动挑选分组或自动开始下一组。

捕获期间发现新群时，确认后让用户从未满组中选择；若没有空位，自动新建插件内的同规格分组。按稳定群 ID 去重，不改写已确认内容或活动批次，新群默认仅用于后续消息。设置页沿用微信原生设置列表、间距和不透明页头；胶囊本身保持克制、贴合微信，不做突兀的品牌浮层。细节仍待视觉稿和真机验证。

当前已实现最低间隔 3 秒、默认 5–10 秒、上限可自定义；上下限相同为固定间隔。用户明确：随机间隔的需求是避免每次等待时长完全相同，让发送节奏更接近日常手动操作，不能将此需求描述为“规避平台规则”。该设置只控制插件自身的调度；平台是否以及如何使用发送频率作为判断因素尚无可靠依据，不作肯定或否定推断。

1. 统一保存母群、来源成员、文字/图片类型和随机间隔，只选不需要发送的排除群；插件按 100/200 群规格自动分规则。
2. 手动等待并确认一条源消息。该内容供本计划全部规则复用，不为每个目标或每条规则重新抓取。
3. 对想执行的那条规则点一次“开始”，内部自动核对账号、目标、资源和发送接口，按节拍串行处理整个规则。不逐群弹窗，不逐群要求确认送达。
4. 用户可随时暂停、手动继续；微信重启后只需选择“继续未发”，不重新配置或复核所有已尝试群。恢复先等待一个新间隔，不补偿性连发。
5. 当前规则结束显示实际记录的完成时间和汇总。下一条始终由用户决定何时点开始，不自动接力。

进度主要展示已处理/总数、已提交、失败及结果未知数量。默认只按需列异常，不刷满每个已提交群。诊断导出保留给维护使用，不是开始、继续或完成的前置条件。

开发时少量测试群的验收不等于产品需要逐群人工确认；当前单群实验的默认关闭和二次确认仍是已交付测试包的边界，不能因此把长期产品也设计成一堆实验步骤。

## 自动处理与真实结果

- **已提交**：适配器已经核对实际宿主调用和身份，取得提交证据，可以继续排队的下一个群；不表示目标群已确认收到。
- **确认送达**：必须有可靠的关联回执。不能仅凭发送方法返回、status 数字或非零服务器 ID 自动写入。
- **明确的目标局部失败**：例如有依据证明某个目标已不可用，保留失败记录并跳过，不要求用户逐个处理，不自动重试该群。不能把账号、服务、网络不确定或平台限制猜成普通目标失败。
- **真正结果未知或执行环境异常**：保留当前尝试，停止后续派发；提示一次清晰的异常原因。用户之后点一次“继续未发”时只处理 pending，不重发已提交、失败或未知的群，不要求先逐群复核。
- **执行完成**：本条队列已处理完，而不是承诺所有目标均已送达。汇总保留失败/未知数量，不能把异常抹掉或把“已提交”偷换成“成功”。

自动检查、有限精确身份读取和资源生命周期管理放在插件内部，不需要用户盯着“观察中”。随机节拍控制范围和速度，不保证不会触发平台限制；明确限制必须停止，不能自动绕过或切下一条规则继续。

## 已实现的核心与小群接入

后续开发版本为 0.2.17，本轮已生成待手机验证包，见下文交付记录；手机上的 0.2.16 不包含这些改动。

- 早期核心 schema 6 增加 `submission_receipts`；本轮接入升至 schema 7，追加 `small_group_runs` 和 `native_attempt_claims`。不重建或删除原表，不清已有实验占位、计划、配置或媒体引用。新增表只存内部标识和时间，不存聊天内容。升级后不要降级旧包。
- 提交证据与实际投递结果分离：原 delivery 保留 uncertain，事务性增加提交记录；统计投影为 submitted，而不是 confirmed。重复回调不会重复记账或擦掉提交证据。
- runner 接受 submitted 后按已有节拍继续下一个 pending；正常规则不再因缺少自动送达回执而逐群要求人工介入。
- 暂停期间有在途尝试时先等其完成/超时，不能一边重置调度一边再次派发。中断在途尝试恢复为 uncertain，其他 pending 保留；重启不会自动开始发送。
- 用户明确继续后只 claim 从未尝试的 pending，未知/失败目标从不回到 pending。环境恢复本身不自动续跑。
- 队列耗尽自动记录 completed 和结束时间，包括存在异常的情况；不要求再手动“收尾”，也不自动启动下一规则。重启时最后一个在途尝试变未知但没有剩余 pending，可结束本条处理并保留异常。
- 历史页区分已提交与确认送达，异常页排除普通提交记录，不加入逐群人工核对按钮或人工修改成功的流程。

## 本轮接入：1–3 群真机检查点

- 新增 `SRSmallGroupSession`，把原有文字/图片单次 host 接到规则 runner。每次真实派发前事务性占用 delivery/attempt，之后不退还、不盲重试；不重置旧 host 的 consumed 门禁，而是为一个已授权的尝试创建一个单次 host。与旧单群实验互斥。
- 开始入口位于已确认内容计划的规则菜单，先展示准确的目标和间隔，再由用户明确开始。仅允许每条 1–3 个授权群，不开放重新执行或大规则发送。一次开始处理本条 pending，不自动接下一条。
- 必须具备原调用已返回、精确本地回读关联本地和服务器 ID、无身份冲突/服务错误等证据，才能投影为 submitted；图片还要求资源校验和 setter 调用。不是把旧 host 的所有 uncertain 改成 submitted，也不宣称确认送达。
- UIKit 和宿主实际调用通过主线程异步桥接，runner 不同步等待主线程。下一次随机间隔从本次结果处理后起算，避免主线程繁忙压缩间隔；有限观察会让实际发送间隔大于设置上限，不保证严格落在该区间。
- 主入口和 native 设置风格不变。微信在前台时可以离开设置页，切换聊天、回复或进入视频号本身不暂停；单独的可拖动进度胶囊提供暂停/继续。切后台、锁屏或账号变化仍暂停，恢复环境不自动继续。常亮只由运行/在途生命周期持有并恢复原值。
