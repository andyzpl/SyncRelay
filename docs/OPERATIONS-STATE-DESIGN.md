## 事件契约

| 事件 | 前提 | 结果 |
| --- | --- | --- |
| 恢复 | 调用方已核对稳定账号并读到该账号记录 | 运行/暂停收尾一律恢复为待手动继续；默认非前台且来源证据未验证 |
| 开启已落盘 | 当前账号可信，存储事务已成功 | 更新开关、使旧捕获代次失效，不启动发送 |
| 进入前台 | 同账号生命周期事件 | 恢复可见性，只有无占用且来源证据可信时可捕获 |
| 候选已落盘 | 当前代次允许捕获，唯一候选事务已提交 | 占用内容、准备状态，旧捕获代次失效 |
| 素材就绪 | 当前占用处于准备状态 | 待转发；文字可立即由调用方提交此事件 |
| 手动开始已获执行器接受 | 前台、开启、占用、无故障；待转发/暂停/本组完成 | 运行；连续点击不得重复启动 |
| 后台/关闭/暂停 | 生命周期或明确操作 | 立即禁止新派发，运行进入暂停收尾 |
| 只读采样短暂 inactive | 前台页面/系统过渡 | 2 秒单调时钟宽限；回 active 取消；超时停止并释放 receiver，不自动重开 |
| 在途收尾 | 暂停收尾状态 | 暂停，不自动继续 |
| 运行完成 | 本内容运行或收尾 | 本组完成，继续占用，不自动下一组 |
| 结束内容已落盘 | 非运行/收尾，事务已归档 | 解除占用，完成摘要保持可见，允许再次捕获 |
| 账号无法核对/变化 | 先禁止旧账号派发 | 清除内存投影，不删除旧账号数据库；下一账号不能直接读取其保存开关自动启用 |

`generation` 是进程内捕获/异步投影令牌，不作为发送回执丢弃依据。关闭、后台、配置变化等令旧捕获无效。发送回执仍由既有 session/runner 按原 account/run/attempt 落盘；协调器重新读取当前账号运行，再用**当前**代次更新投影。不能把旧发送回执原样交给捕获代次过滤而丢失结果。

`sourceVerified`、`fault` 是协调器的输入证据，不是 UI 可设置的开关。模型不验证宿主、不执行持久化、不自行清除故障。它也不替代执行器的 20 群校验、互斥和 pending-only 限制。

## 协调器现状与宿主接入

SRRelayCoordinator 核心及捕获/执行端口已新增，无 UI 测试已编写；仍未接入 SREntry/receiver 或替换现有页面控制入口。

单一主线程 `SRRelayCoordinator` 当前依赖 store、捕获控制端口、执行端口和状态机，不直接持有 UIKit 或调用宿主发送。C 接线时由同一生命周期 owner 连接 receiver/small-group session；SREntry 只桥接账号/前后台/窗口，设置页不拥有监听。

1. 启动先核对账号、读取持久状态并恢复 interrupted runs。只有同账号进程恢复允许采用保存开关；进程内发生账号变化则进入安全关闭，要求该账号重新开启。
2. 操作顺序为：校验 → 持久化 → 更新模型 → 发出状态通知。UI 读取快照不能产生上述操作。
3. 暂停等安全操作立即撤销派发许可，再调用 session 公开暂停入口。写盘失败时保持安全停止并显示故障，不用旧开关成功状态掩盖失败。
4. 配置版本、账号及捕获代次共同绑定异步素材回调。配置变化不能修改已占用的冻结配置；只有新监听采用新配置。
5. 开始操作由协调器串行化；计划创建成功后保存关联 ID，启动失败保留计划和原因，后续重试只启动同一计划规则。
6. 第四批将编辑配置读取失败与冻结任务读取分开：编辑配置损坏仍投影缺项/故障并暂停派发，但可信的冻结任务可暂停、取消或归档。`stateLoaded` 表示任务投影可核对，不代表配置可用；发送仍受开关、requirements 和 fault 共同限制。修好配置不自动续发或重新监听，需显式重新开启。
7. 安全命令按其持久结果复核，不因编辑配置仍损坏而把已确认的取消/归档误报为失败。任务投影读回失败或账号变化则不报成功，并说明已落盘的操作需要重新读取；不通过回滚真实取消来伪造旧状态。已接回运行的重复接回不清故障、不重建记录，也不撤销健康运行的手动继续许可。
8. 第五批公开命令必须携带当时显示的稳定账号，并分别绑定内容 ID、冻结规则 ID 或运行 ID；开始、准备和结束均绑定内容，暂停/继续/取消绑定运行；不再提供不带对象的“操作当前任务”入口。UI 确认闭包保存原标识，晚回调不能拿最新快照替换对象。开始先核对本内容已有冻结分组，拒绝旧分组时不为新内容建立计划；归档读回失败后可用最近归档原内容 ID 幂等确认，不改日期、不解除故障、不结束替代内容。
9. 第九批把配置编辑保存后的刷新也绑定页面显示账号：`configurationSavedForAccount` 先核对宿主当前账号，再 reload 并复核同一账号；旧页面回调不能借配置刷新触发账号切换的安全关闭或改写新账号状态。
10. 第九批运行卡片新增只读 `creationOrder`，沿用历史查询已有的 `runs.rowid` 插入顺序；协调器无活动运行时据此选最近记录，时间回拨或同值不再把本组结果投影成旧组。`started_at` / `ended_at` 仍是原始业务时间，不被排序修正或刷新改写。
11. 第十批将账号预检扩展至异步捕获：监听代次与 envelope 账号先匹配原 owner，再核对当前宿主账号，之后才能 reload。旧/错误 owner 的回调不承担生命周期迁移职责，不能改写新账号偏好或触发无关读盘故障；真实生命周期刷新仍负责账号切换安全关闭。预检通过后保留配置重读及代次复核，不接受保存新条件前产生的素材。
12. 第十批最近归档投影也使用持久插入顺序：同账号新内容只能在原内容归档后创建，因此 `operations_contents.rowid` 的顺序与占用结束顺序一致。`archived_at` 只作为实际日期，不作为“最近”排序依据；归档读回失败的原 ID 重试不受墙钟回拨影响，也不改写日期或替代内容。
13. 第十一批延后生命周期本身就是停派条件：端口返回后不能因最后一次通知是前台就补回手动许可。`SROpsPauseRequired` 集中判断账号可信/开关/前台/配置/故障/待处理通知，再由协调器对持久 running 端口暂停并有界读回；延后通知收尾前再次清空 `manualRun`。健康单次重入保持开关、原内容和 pending，后续需用户手动继续，不自动恢复或额外要求重新开启。
14. 第十二批故障同样撤销手动许可，并在调用捕获/执行端口前完成；不能只设置故障位而保留 `manualRun`。暂停失败或虚报时，后续开启即使尝试清故障也不能沿旧许可恢复派发；端口恢复并实际暂停后，仍需明确继续。该变化不清 claim、不丢弃在途回执、不重建任务。

## 第十三批库任务占用与协调器门禁（A-3 返修）
