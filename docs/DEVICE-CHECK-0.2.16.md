## 安装前

- 只使用一个由你授权的测试群，先关闭其他自动发消息功能。不要测试 100/200 群规则或真实业务大群。
- 本轮普通包版本应为 0.2.16；覆盖升级，不卸载、不清配置、数据库或既有实验占位。数据库增加独立图片占位表并升级为 schema 5；不要降回旧包，旧版不能安全读取新 schema。
- 文字和图片实验默认关闭，两者共用一次微信进程机会。图片在资源装载前就消耗本次进程机会；装载失败也不重试。跨重启的来源占位独立保留，重启不会释放已使用的源消息。

## 第一次：仅测一张小图、一个目标

1. 安装本轮核验包，完全退出并重开微信。在「我 → 设置 → SyncRelay 转发 → 运行诊断」确认版本、源码提交及 CI run 与包记录一致；两个实验开关先保持关闭。
2. 保存母群、来源成员 wxid（可以选本人）、图片类型和目标规则。建议本轮只留一个测试目标；即使已有较多规则，实验也只能手动选其中一个非母群、未排除且当前仍可读取的群。间隔建议先固定 10 秒，或 10–20 秒随机；本轮单群实验支持 10–3600 秒范围。
3. 点“等待源消息”，关闭面板回母群，由所选成员发一张新的普通静态小图。先用截图或小照片，不用动画、大图或透明素材。本轮发送上限为 1600 万像素、单边 8192 像素，发送素材不超过 20 MiB；更大的捕获快照不进入实验。
4. 回插件打开实际图片预览，核对确实为刚发的图片、母群及发送者。返回插件主页面，**不要点确认创建计划**；单群实验使用尚未转成计划的冻结预览。无需重复上轮“图片发送接口检查”。
5. 在“更多设置”明确开启“单群图片实验发送”，保持文字实验关闭；再到“源消息与计划”点“单群图片发送（实验）”，只选一个授权测试群并进行最后确认。
6. 保持微信前台和当前实验页面，等待显示的间隔。等待及最多 30 秒精确身份观察期间插件请求常亮，但不阻止你手动锁屏；锁屏、切后台、关闭面板、修改设置或账号改变会取消等待/停止观察，回前台不会自动接着发送。
7. 只操作一次。结果出现后核对目标群是否收到、是否只有一张、图片内容和方向是否正确；导出运行诊断。请同时反馈“收到/没收到、几张、内容/方向是否正确”。

## 结果如何理解

- “已调用，送达待核对”只说明发送入口被调用。非零本地/服务器 ID、status 或有限回读均不证明图片内容及实际送达。
- “发送门禁阻断”需导出诊断，不反复点、不重启重试同一张来源、不清占位。原生图片 setter 即使没有随后调用发送入口，也可能已写入微信本地媒体文件；不删除猜测路径、不自动清理宿主资源。
- 发送的是已加载静态快照生成的质量参数 0.95 的 JPEG，不是保留原文件、原图质量、透明通道或动画的承诺。方向异常、压缩不符或缺图要保留现场和诊断，不切换另一接口盲试。
- 需要再测时，先把本次结果交给开发者分析；后续使用新源消息、重新显式确认。旧源的持久占位永远不作为自动重试入口。

## 新诊断

`singleImageSendCandidate` 与原有 `imageSendPreparation` 分开：前者记录真实实验阶段，后者仍仅是“不发送”的独立接口检查。新字段包括 `attemptConsumed`、`materialValidated`、`materialEncoding`、`imageMethods`、`imageSetterInvoked`、`nativeImageSideEffectsPossible`、`selectedSelector`、`submissionAttempted`、服务契约与有限精确 ID 观察。

`imageContentVerified=false`，调用后 `deliveryOutcome=uncertain`；不自动标记成功。另有 `singleImageExperimentHistory`、实验开关/倒计时/常亮占用与四种固定事件；不导出图片、数据、文件路径、真实 ID 或对象描述。原始手机报告不提交公开仓库。

## 未验证范围

本地语法、模拟服务/图片对象和 CI 构建不能代替手机验证。后续已有本机一次 JPEG 素材装载/提交记录及单群成功反馈，范围见结果文档；不据此涵盖所有尺寸/来源、方向/重复条数、原生异步媒体完整生命周期。微信 8.0.76、其他设备/版本、原图/动画、批量、暂停继续与批量重启恢复均不在本轮验收范围。
