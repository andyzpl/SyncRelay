# 手动文字接收候选与单条计划

日期：2026-10-20。状态：源码与模拟测试开发阶段，不是已通过手机验证的微信兼容性结论。本轮不打包，不发送。

## 依据和边界

原 MikotoHelper 静态报告可定位 `AsyncOnAddMsg:MsgWrap:`、`m_nsRealChatUsr`、`m_uiMessageType`、`m_n64MesSvrID`、`m_nsContent`、`m_nsFromUsr`、`m_nsToUsr` 等选择器。它们只是候选线索，不证明所属类、方法实现或两版实际 ABI/语义。

本项目自行编写 `Adapter/SRWeChatReceiver.m`，使用 `CMessageMgr` 和 `CMessageWrap` 作为待核对运行时类名，不复制或调用第三方插件代码，不修改授权逻辑。目标版本仍为 8.0.76 / 8.0.79，均未真机确认。

## 何时观察

- 启动仅构建捕获器与候选对象，不安装接收 hook，不监听、不建立运行批次。
- 用户先保存草稿，再明确点击“等待一条母群文字”。必须核对当前账号、来源群及捕获配置；纯图片配置、本人成为唯一来源或缺少规则时不进入可用等待。
- 安装前检查候选入口为 `void(object, object)`；检查四个字符串 getter 和两个整数 getter 的签名。缺少类/方法、类型错误或未知版本即停止。
- 观察器先调用原接收实现，保留原参数与原有异常语义；只对附加观察部分捕获异常，不能改变微信原消息处理结果。
- 每个候选类只安装一层本项目 wrapper，同一类同时只有一个监听器。停止时解除监听并失效旧回调，不擅自拆除可能被其他插件串接的运行时方法链；wrapper 保留到进程退出，未等待时只调用原方法。
- 实际与其他插件的 hook 顺序、arm64e 行为及线程语义必须真机核对；签名匹配不能证明这些行为已经兼容。

## 读取与过滤

只处理会话参数等于所选母群的候选事件，并要求：

1. `m_nsFromUsr` 等于母群原始 ID，`m_nsToUsr` 等于已核对的当前账号。
2. `m_nsRealChatUsr` 非空、非群 ID、无空白，并且不是本人；随后由捕获核心与已选来源 wxid 精确匹配，不推断昵称或正文前缀。
3. `m_uiMessageType` 是整数 1，只接收文字；不把图片 XML/引用当作可用文件。
4. `m_n64MesSvrID` 是非负整数 getter 的非零值，完整转为 `svr:<十进制整数>`；没有 double 中转，不丢失超过 2^53 的整数精度，不回退本地临时 ID。
5. `m_nsContent` 是非空字符串。当前保持原字段内容，不未经设备验证就剥除疑似群消息前缀或重建消息正文。

通过“来自其他成员且发给当前账号”的方向检查后，规范化数据标记 `generatedByRelay=false`；本插件只可能以当前账号发送，因此排除本人回显。该标记不证明其他成员未使用其他自动化工具。

读取后立即深冻结，主线程交付前再次核对账号和本次等待代次。取消、重新等待或账号变化后，旧队列回调失效。第一条匹配后停止，不以第二条覆盖第一条。

本候选只观察开始等待后进入该回调的数据，不主动扫描历史。回调是否包含离线补同步、字段是否与屏幕消息一致、类型枚举与服务器 ID 是否符合假设，都需要真机实测；当前不能承诺只收到“刚由人新建”的消息。用户必须核对预览再确认，且确认不发送。

## 界面和持久化

- 等待时可关闭插件面板回母群；捕获到内容后入口显示“预览”，不会自动弹出确认或发送。
- 预览显示群 ID、实际发送者 wxid、类型、源 ID、可打开的完整正文，以及捕获时冻结的规则数量/目标数量/间隔。放弃不建计划。
- 确认走现有原子事务：源 claim、计划、规则和目标一起提交；重复源不生成另一份计划，失败保留预览。无论成功还是失败，都不会启动任何规则。
- 已确认计划和执行历史独立于草稿。修改其他草稿条件不会替换已有预览的冻结配置；更换母群会先确认并取消未确认捕获。
- 等待期间修改草稿或应用失去前台活跃状态时取消等待；回前台不自动重启。预览可在内存中保留，但账号变化会清除，进程退出不保证保留未确认预览。
- 完整正文页失去前台活跃状态时清空显示，重新出现或回前台必须再次核对账号；核对失败时丢弃该页正文，不沿用无账号检查的通用文本查看器。实际切换/遮罩效果仍待设备验收。
- 确认后的计划支持按账号分页读取；规则显示最近批次、原始结束时间及汇总，历史可展开异常群。成功群不逐项刷屏，失败/待核对/取消明确区分。
- 只读页面不直接调用 `SRRunner`，没有假发送器、测试消息注入入口或可用的开始/继续/重新执行按钮。

## 测试范围

`tests/receive_test.m` 用模拟类调用真实生产候选实现，检查签名拒绝、整数 getter、原接收链保留、继承链、文字/wxid/群/账号过滤、精确大整数 ID、外部变更不污染预览、取消旧代次及账号切换。

`tests/plan_queries_test.m` 检查账号隔离、计划/历史/异常分页、顺序状态提示、真实结束时间保持、失败和待核对分开、取消群、重开恢复及只读不自动建立新批次。正文只在显式计划详情中读取，不进入历史列表。

模拟调用并非微信真实回调；本机语法检查不是 UIKit 运行或设备验收。手机验收步骤见 `DEVICE-CHECK-0.2.0.md`。下一阶段仍需验证最小文字接收，再核对文字发送接口和可靠结果事件，最后接入执行控制与媒体，不在本轮直接向大批量群发送。
