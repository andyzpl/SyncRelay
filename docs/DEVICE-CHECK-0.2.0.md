# 0.2.0 设备验证清单

本清单针对已明确生成的首轮手机诊断开发包，旧 DEB 不自动包含新增代码。打包提交 `c9bec6e`，私有流水线 `39434037504`；本地文件为 `dist/0.2.0-test-39434037504/andyz.syncrelay_0.2.0_iphoneos-arm.deb`。
源码现支持手动启用文字接收候选和一次手动文字发送的只读观察；插件不代发、不自动开始规则。观察环节只需用户在微信正常发送一条普通文字，不需要用真实大批量群发测试。
目标 iOS 16.0.3，微信 8.0.76 / 8.0.79；两版分别验证。不要把 macOS 模拟测试视作微信兼容性证明。

当前开始第一轮小范围手机验证：先只读数据和配置，再接收预览，最后一个授权测试群的一次手动发文字观察。本次已明确启用 `build_deb` 并构建成功；未做 100/200 群实发或长期运行验收，不将本清单当作兼容性承诺。

## 本次先测这三项

1. 用现有注入工具加载普通 DEB，结束微信进程后重开，核对右下角“同步”入口、当前账号 ID、群数量和成员 wxid。读取失败时先复制“查看适配诊断”的报告；闪退则先停用本测试插件并回传崩溃报告，不反复启用测试。
2. 用一个授权母群、另一位来源成员和 1–2 个授权目标保存小草稿，手动等待一条文字。核对预览的群、发送者和正文；确认只建计划，不发送。
3. 取消等待后，选“只读观察一次手动文字发送”，仅选一个授权群。关闭面板后在 120 秒内去该群正常手动发一条普通文字，稍候返回停止观察，打开适配诊断并复制报告。观察不到或状态变化不等于发送失败/成功，不为此补发多条。

先回传设置首页截图、脱敏适配诊断、微信版本/构建号及注入方式即可；如测试了接收或手动发送，再注明屏幕实际结果。截图中的账号、群名/ID和正文请按需要遮盖。后面的清单用于进一步检查，不要求第一轮一次全部做完。

## 安装与入口

1. 使用现有工具将普通 DEB 加载到微信。结束微信进程后重新打开。
2. 登录后观察右下方“同步”入口，点击进入。若完全没有入口，记录微信版本及构建号、注入方式和截图，不反复尝试发送。
3. 本版浮动入口是诊断期入口，不修改微信设置页面；设置采用原生全屏导航，点“关闭”返回微信。

## 先核对只读数据

1. 顶部显示的账号原始 ID 是否为当前账号；读取失败时，打开“查看适配诊断”，点“复制”回传。
2. 选择母群，核对群名和群 ID；记录列出的群数量。当前接口可能只覆盖部分群，不把“全选”理解为微信所有已加入群。
3. 指定发送者，核对原始 wxid；同昵称的两个人是否显示不同 ID。昵称缺失时显示原始 ID，不猜昵称。
4. 若群成员读取失败，先在微信打开母群，再返回重试；仍失败则提供诊断，不手工绕过稳定 ID 检查。

## 验证配置草稿

1. 勾选文字/图片，关闭最后一项时应被阻止。
2. 设置 10–20 秒并保存；9–20、20–10 或非整数输入应被拒绝。
3. “搜索并排除群聊”：按名称或 ID 搜索后勾选排除；“排除搜索结果/恢复搜索结果”只修改当前匹配项；“排除全部可选群/取消全部排除”作用于完整列表。零个排除也能应用。
4. “自动分配规则”：两个输入框分别标明 100 群/条、200 群/条。各填 10，在群足够时预览 20 条/3000 群；检查实际可分配、缺口和剩余，点取消不得改变草稿。
5. 数量不足时仍能预览和确认，只保留实际有目标的规则，最后一条可不足额。全部排除时提示无新增规则，不创建空规则。
6. 确认生成后查看任意规则，所有规则共用母群、wxid、类型和间隔；修改一次统一条件后，不需逐条设置。重复生成须自动排除之前分配的群和母群，保留原规则。
7. 用“手动选择并分组”全选超过 200 个可选目标，应按每条不超过 200 群拆分，不产生一个超大批次；该入口全选作用于完整可选列表，不限搜索结果。
8. 新增排除命中已有规则时，应确认移除目标数和空规则数；取消不改变任何草稿。应用后其他规则不自动重排，解除排除也不自动补齐。
9. “保存草稿”，关闭再打开，应恢复统一来源、发送者、类型、间隔、排除群与分组。旧版无排除字段的草稿应仍能读取；从本地群列表临时消失的排除项仍应保留。
10. 修改后关闭，选择继续编辑应保留输入；选择放弃应保留最后一次已保存的草稿。
11. 更换母群时，有发送者或分组应先确认清空；取消保持原配置，排除列表不因更换母群被清空。
12. 删除未执行分组后，其中未排除目标可以重新分配；保存后重新打开核对。
13. 切换微信账号后，旧面板操作或旧分配预览应停止；关闭重开后读取新账号草稿，不能覆盖旧账号配置。

## 验证手动文字接收候选

1. 仅用一个授权母群和 1–2 个授权目标建立小草稿，选择另一位成员的 wxid，允许文字并保存。当前不能以本人为唯一来源或仅等待图片。
2. 先不点“等待”，让成员发一条文字，插件不得自行出现预览、内容计划或运行记录。
3. 手动点“等待一条母群文字”，候选类/接口不匹配时应立即停止；复制适配诊断，勿反复切换未知 API 参数。
4. 关闭面板回母群。其他群、未选发送者、图片、本人消息不应成为预览；由已选成员发一条短文字后，“同步”入口应变为“预览”。核对母群 ID、实际 wxid、服务器 ID 及正文是否与屏幕一致。
5. 特别核对正文是否带原始群消息前缀、ID 是否非零稳定、离线补同步是否进入该回调。若不符合假设，停止验收，不把签名检查成功当作兼容通过。
6. 再发第二条，不应替换第一条预览；放弃不应留下内容计划。重新手动等待后，在预览确认应建立规则，所有规则均仍显示未执行，没有任何实际发送。
7. 文字很长或含 emoji/组合字符时，摘要和完整查看不得破坏字符；预览展示捕获时冻结的配置，不能偷偷变成后来修改的草稿。
8. 等待期间编辑草稿、锁屏、切后台或离开活跃状态后，不再继续监听；回前台不自动重新等待。切换账号后旧预览和旧回调不得写入新账号。完整正文查看页失去前台活跃状态时应隐藏正文，回前台重新核对账号；无法核对时不得重新显示旧正文。
9. 退出重开后未确认预览需要重新捕获；已确认计划应恢复且仍不自动运行。新计划只有未执行规则，不制造假完成时间；已有批次的结束时间/异常显示待后续真实发送阶段验证，目前仅由核心模拟用例覆盖。
10. 两版微信分别记录构建号、注入环境、候选签名与实测结果；本轮无设备，不预先勾选通过。

## 验证一次手动文字发送观察

1. 先取消源消息等待；两种观察不能同时开启。已有接收预览可保留，不应被本次观察覆盖。
2. 在“适配状态”点“只读观察一次手动文字发送”，搜索并只选一个授权测试群，确认“开启观察（不代发）”。未知版本或接口编码不匹配应停止并给出诊断，不自行改 API 参数绕过。
3. 暂停其他自动发消息功能，关闭面板，120 秒内到所选群用微信正常手动发一条短文字。没有预览时入口应显示“观察”；不要为了测试连续发多条。插件不自己补发或建立运行批次。
4. 观察微信屏幕上的发送中、发送后或错误表现；返回面板，先点“停止手动发送观察”，再进入“查看适配诊断”复制。诊断页是进入时快照，不是实时刷新的状态面板；报告不持久保存，退出微信前先复制。
5. 检查 `manualSendObservation` 的 ABI、`observedOutgoing`、`samples`、`lookupMisses` 等原始信息。可能有 `after_add` / `live_wrap` / `local_readback` 样本；ID 存在或原始状态变化不代表本插件已确认送达。`sendingEnabled` 必须是 false，`deliveryOutcome` 始终是 `not_determined`。
6. 如果没有观测到、读取未匹配或身份冲突，保留报告和屏幕实际结果；不要把它标为发送失败、自动重试或改查其他消息。先停止并回传用于适配。当前未监听 `MessageReturn...` 作为回执。
7. 分别检查取消选择/确认不装监听、手动停止后不继续采样、120 秒期限停止；切后台/锁屏停止且回前台不重开。需要重复验证时必须重新手动开启。
8. 账号变化时观察应停止并清空旧样本；旧排队回调不能混入新一轮。其他群、他人消息或图片不得作为这条普通文字的观察对象，不需额外发送大量消息验证。
9. 回传微信版本与构建号、iOS/设备/注入方式、是否共存其他插件、手动发送的大致时间、屏幕显示结果和脱敏报告。截图请遮盖消息正文、个人及群信息。不要求提供原始消息 ID。

详细过滤、ID 读取、容量上限和证据边界见 `SEND-PROBE.md`；原包调用点见 `MIKOTO-SEND-EVIDENCE.md`。这些验证只为之后独立实现文字发送提供依据，不是自动转发功能已完成。

## 视觉与交互检查

- 小屏、长群名、长 wxid、较大系统字号下无按钮遮挡和关键信息裁切。
- 搜索、选择勾号、导航返回、保存反馈正常；打开/关闭设置不影响微信原功能。
- 自动分配的两个数字框标签清楚，预览内容可完整阅读；大字号、长群 ID 下确认/取消均可用。
- 本轮开发环境没有 iPhone 画面，未完成真机视觉/交互验收；请提供设置首页、选群、成员页及错误页截图。

诊断报告包含系统/微信版本、接口签名、固定提示，以及手动发送观察的有限计数、ID 存在/冲突布尔值与原始状态码；不含账号 wxid、群名单、原始消息 ID 或正文。截图中的个人 ID 请按需要遮盖。
本版不需要启用防锁屏；常亮只会在未来真正执行批次时开启。
