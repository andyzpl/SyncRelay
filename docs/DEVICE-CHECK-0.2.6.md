# 0.2.6 消息字符串读取修正真机检查

日期：2026-10-21。目标仍为 iOS 16.0.3、微信 8.0.76 / 8.0.79；目前设备报告只覆盖 8.0.79.35，不能泛化为两版已兼容。真实转发仍关闭。

## 目的与包状态

0.2.5 已确认母群会话的 CMessageWrap 文字回调到达，但 from/to/real sender 的旧实例反射签名路径全部拒绝（state 2），不是已经读到字符串后判定 ID 错误。0.2.6 对真实存在的消息字符串 getter 按 runtime 方法编码严格校验后派发读取，不再依赖对象自报的反射签名；未知真实 ABI 仍拒绝，不使用 ivar/KVC 或猜 ID。

本地 54 项双架构语法、12 项 Python 解析测试通过。编译源码固定为 `2d27fdd34b227da4778e0572e31ff6686fe64ebe`；[私有构建 39464466046](https://github.com/andyzpl/SyncRelay/actions/runs/39464466046)，job `118772113245`，北京时间 2026-10-21 01:15 派发，最终因未能分配 hosted runner 而失败（job cancelled，steps 为空，artifact 0），GitHub 同时提示 macOS ARM 容量不足。核心运行测试/打包都未执行，没有 0.2.6 包或哈希；日志接口返回 404，失败依据为 check-run 注释，不编造编译日志。此修正随 0.2.7 继续验证，改用 Intel macOS runner，步骤以 `DEVICE-CHECK-0.2.7.md` 为准；以下仅保留历史预案，不要求重测旧包。

## 手机步骤

1. 安装 0.2.6，完全结束微信后重开，确认插件版本；无需重建分组或更换母群。
2. 保留小范围目标规则，确认来源为“我”、文字已启用并保存，然后开始等待。
3. 关闭插件面板回母群，本人发一条普通文字，保持微信前台、不锁屏。若仍未预览，等待约 30 秒。
4. 无论有没有预览，都先导出运行诊断，回传 JSON 和发送时间。不要在导出前重启、重新开启一轮等待或改来源条件；样本只有内存本轮最多 12 条。
5. 如有预览，核对母群、本人 wxid、正文和源 ID。确认仅建立内容计划，不发送；本轮不运行 100/200 群规则。

## 重点验收

- build 应为 0.2.6 的确切提交/run；`directionEvidenceSchema = 2`，`stringReadStrategy = declared_runtime`。
- from/to 状态预期从原先的 2 变为 7，并形成正确账号/母群关系；本人 real sender 可为 nil（4），仍由明确本人方向和当前账号校验约束。
- 旧 `*InstanceSignatureState` 即使仍为 2，也不影响真实声明读取；如真实读取仍不成功，保留具体状态，不伪造成功或放宽 ID 校验。
- 若方向通过后改为 `receive_no_server_id`、`own_pending` 或 `own_timeout`，说明卡点已推进到 ID 阶段，需根据新证据定位，不能据此提前认定捕获全部完成。
- 报告不得出现原始 wxid、群 ID、消息 ID、正文或异常文本；预览页显示真实来源供用户核对，与报告脱敏分开。
- 实机来源群/wxid/ID、原方法链和生命周期仍需验收，模拟 fixture 的读取成功不是微信手机成功结论。

维护与字段说明见 `RUNTIME-DIAGNOSTICS.md`。
