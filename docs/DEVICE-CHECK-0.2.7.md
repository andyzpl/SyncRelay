## 手机步骤

1. 安装本轮 0.2.7，完全结束微信后重开，进入「我 → 设置 → SyncRelay 转发」，核对版本；旧配置应保留，不需重建分组。
2. 查看顶部标题与状态栏区域：上下滚动、进入群搜索及成员页、返回、切换深浅色后应始终不透明，不透出列表文字；微信自己的设置页样式不应受影响。可回传截图核对实际布局。
3. 右上角应为“保存”，修改条件后页脚提示先保存，成功提示“已保存”；不再出现“保存草稿”。修改后关闭仍需确认，放弃只丢弃未保存修改；重新打开应恢复上次已保存设置。
4. 保留 1 条小范围目标规则，确认母群、来源“我”和文字开关，点“保存”，再手动“等待一条母群文字”。本轮不操作 100/200 群批量发送。
5. 关闭面板回母群，由本人手动发一条普通文字，保持微信前台、不锁屏；若未预览，等待约 30 秒。
6. 不论是否预览，先导出运行诊断，回传 JSON 和发送时间。导出前不要重启、重开等待或改条件，本轮方向样本仅在内存且上限 12 条。
7. 如有预览，核对群、本人 wxid、完整正文和源消息 ID。确认仅建立内容计划，不发送。其余成员路径可在本人测试后另开一轮单独验证。

## 已完成：单群手动发送观察

这一步仍然不调用插件发送接口。目的是先确认微信正常发送时 `AddMsg:MsgWrap:` 的实际 ABI、线程、local/server ID 关联和原始状态变化，为后续单群主动发送适配提供证据。已收到一份 8.0.79.35 报告，结果见下方；后续不把该报告当作主动发送成功证明。

1. 在“源消息预览”确认内容，进入“内容计划与规则”；确认动作只建立计划，不发送。
2. 返回「我 → 设置 → SyncRelay 转发」，在“更多设置”点击“手动发送观察”。从群列表只选一个你明确授权的测试群，确认“开启观察（不代发）”。源消息等待不能同时处于等待状态。
3. 关闭面板，回该测试群，用微信原生输入框手动发送一条普通文字；不要连续发送，也不要启用其他自动发消息插件。保持前台、不锁屏，最多等待 120 秒。
4. 回到插件先点击“停止发送观察”，再进入“运行诊断”导出 JSON。不要在导出前重启微信或重新开启观察。
5. 同时记录微信屏幕上显示的发送中、发送后或错误状态；不要把屏幕显示或诊断中的 ID 直接解释为送达成功。

预期报告字段：`manualSendObservation.observerOnly = true`、`sendingEnabled = false`、`deliveryOutcome = not_determined`。`observedOutgoing`、`samples`、`lookupMisses` 和 `identityConflicts` 只用于适配判断，不是成功/失败数量。无观测、ID 未出现或状态变化都先保留报告，不补发、不重试。

这一步完成后，才评估是否实现“单群主动文字测试”。主动测试必须继续保持单目标、用户每次明确确认、账号/目标 wxid 严格核对、无自动重试；没有可靠结果回执时仍显示“待核对”，不进入 100/200 群规则执行。

## 诊断重点

- build 应为本轮 0.2.7 的确切源码提交/run，不是 0.2.5；`directionEvidenceSchema = 2`、`stringReadStrategy = declared_runtime`。
- from/to 预期从旧 2 变为 7，仍须来源群/账号关系正确；本人 real sender 可为 nil（4），不因此绕过本人方向核验。
- `*InstanceSignatureState` 可仍为 2；真实声明读取若成功则不依赖该旧路径。实际 ABI 不符仍停止，不猜 wxid/群 ID。
- 方向通过但进入 `receive_no_server_id`、`own_pending` 或 `own_timeout` 只说明推进到 ID 阶段，不代表最终捕获或送达。
- 原账号隔离、母群自动排除、已确认计划/历史保持不变；报告不得包含正文或原始账号/群/消息 ID。

界面源码检查不等于实际不透明/布局验收；macOS 模拟测试不等于微信手机兼容。维护说明见 `RUNTIME-DIAGNOSTICS.md`。

## 已收到的手机结果（2026-10-21）

- 用户表示抓到消息，随后成功诊断的构建提交/run 与上述包一致；iOS 16.0.3、微信 8.0.79.35。配置已保存，来源包括本人，1 条规则/3 个目标，文字与图片配置均勾选，但本次实际只采集文字。
- 01:56:34.163 等待启动，01:56:43.354 本人回调，01:56:44.402 接受后停止；最终 `sourceCapture.state = preview`、offered 1、rejected 0、reason 0。本人发送回调到接受约 1.048 秒。
- from/to 的 runtime 读取状态为 7，fromIsAccount/toIsSource 为 true；旧实例签名状态仍为 2，real sender 为空字符串（6），本人由明确 from/to 方向及当前账号核验，不从空 sender 猜身份。本次验证了声明读取恢复，不证明所有消息/版本均适用。
- 初始 `receive_no_server_id = 1` 后进入 own_pending，并记录一次精确 ID 回读尝试，最终通过非零服务器 ID 门禁；不是以临时 local ID 冒充服务器 ID。报告无法区分最终 ID 来自原 wrap 更新还是回读对象，不作额外推断。
- `armed = false`、receiver_stopped 是锁定第一条后的正常停止；previousLaunch 的方向拒绝为旧启动历史。本轮没有方向拒绝、超时或冲突。
- 报告不含原始 wxid/群 ID/正文，仍需用户核对预览内容；没有确认计划/真实发送验收，手动发送观察仍 idle，sendingEnabled 为 false。群读取为 not_read，3 是配置目标数而非总群数。
- 此次仅标记“本人文字采集进入预览”通过。顶部视觉、他人成员、母群切换、图片、群池完整性、确认落库、投递回执及 8.0.76 兼容仍未由该报告验证。
- `manualSendObservation`：`observedOutgoing = 1`；样本为 `after_add`、两次 `local_readback`，服务器 ID 从不存在变为存在，`lookupMisses = 0`、`identityConflicts = 0`、`droppedSamplesOrCallbacks = 0`。这证明精确本地 ID 关联路径有可继续研究的信号，不证明调用插件主动发送成功或服务器已送达；`deliveryOutcome` 仍为 `not_determined`。
- 下一验收点是源码级单群主动文字适配器模拟：严格 ABI/账号/目标群/源快照门禁、二次确认和 `uncertain` 结果落库；适配器通过前不打新包、不接入 100/200 群执行。
