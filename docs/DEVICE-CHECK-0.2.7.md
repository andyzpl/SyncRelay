0.2.7 将用户可见“草稿”改为“设置/规则”，按钮“保存”、反馈“已保存”，保持原有保存语义。插件自己的导航栏统一不透明，不影响微信其他页面，仍需手机视觉核对。

## 手机步骤

1. 安装本轮 0.2.7，完全结束微信后重开，进入「我 → 设置 → SyncRelay 转发」，核对版本；旧配置应保留，不需重建分组。
2. 查看顶部标题与状态栏区域：上下滚动、进入群搜索及成员页、返回、切换深浅色后应始终不透明，不透出列表文字；微信自己的设置页样式不应受影响。可回传截图核对实际布局。
3. 右上角应为“保存”，修改条件后页脚提示先保存，成功提示“已保存”；不再出现“保存草稿”。修改后关闭仍需确认，放弃只丢弃未保存修改；重新打开应恢复上次已保存设置。
4. 保留 1 条小范围目标规则，确认母群、来源“我”和文字开关，点“保存”，再手动“等待一条母群文字”。本轮不操作 100/200 群批量发送。
5. 关闭面板回母群，由本人手动发一条普通文字，保持微信前台、不锁屏；若未预览，等待约 30 秒。
6. 不论是否预览，先导出运行诊断，回传 JSON 和发送时间。导出前不要重启、重开等待或改条件，本轮方向样本仅在内存且上限 12 条。
7. 如有预览，核对群、本人 wxid、完整正文和源消息 ID。确认仅建立内容计划，不发送。其余成员路径可在本人测试后另开一轮单独验证。

## 诊断重点

- build 应为本轮 0.2.7 的确切源码提交/run，不是 0.2.5；`directionEvidenceSchema = 2`、`stringReadStrategy = declared_runtime`。
- from/to 预期从旧 2 变为 7，仍须来源群/账号关系正确；本人 real sender 可为 nil（4），不因此绕过本人方向核验。
- `*InstanceSignatureState` 可仍为 2；真实声明读取若成功则不依赖该旧路径。实际 ABI 不符仍停止，不猜 wxid/群 ID。
- 方向通过但进入 `receive_no_server_id`、`own_pending` 或 `own_timeout` 只说明推进到 ID 阶段，不代表最终捕获或送达。
- 原账号隔离、母群自动排除、已确认计划/历史保持不变；报告不得包含正文或原始账号/群/消息 ID。

界面源码检查不等于实际不透明/布局验收；macOS 模拟测试不等于微信手机兼容。维护说明见 `RUNTIME-DIAGNOSTICS.md`。
