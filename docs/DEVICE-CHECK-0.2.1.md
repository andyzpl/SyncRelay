# 0.2.1 设置入口与群列表重测

本轮针对 0.2.0 手机反馈：只列出 4 个普通群、不要强制悬浮入口。目标环境仍为 iOS 16.0.3、微信 8.0.76 / 8.0.79。只测只读列表和入口，不做自动发送或大规模群发。

## 安装与入口

1. 用新包替换旧版，保留原草稿和计划数据。结束微信进程再打开；不得出现默认悬浮按钮。
2. 打开「我 → 设置」，找到且仅找到一行「SyncRelay 转发」。点击应进入原生配置面板；关闭应回原设置，不影响微信原有选项。
3. 返回/重进设置、反复打开/关闭面板，不得重复插入入口。若没有入口或微信闪退，先停用本插件，记录微信版本/构建号、注入工具、其他共存插件与崩溃日志；新版不会为了兜底强制弹出悬浮按钮。
4. 面板“开启悬浮入口”初始为关。打开后关闭面板，确认浮动入口出现；关闭开关后立即移除，关闭面板不应复活。分别在开启/关闭后结束进程重开，确认记住选择。该开关即时保存，无需点“保存草稿”。

## 群数量与诊断

1. 选择母群，记录候选群数，并搜索几个以前未返回、确实仍加入的普通群（特别是未保存至通讯录但在会话列表里的群）。不要把“全选”理解为已确认全部已加入群。
2. 打开“查看适配诊断”，复制 `groupRead`、`settingsEntry` 等报告。它包含联系人返回数/群数、会话返回数/群数、未核对数和去重后数，不应包含群名、群 ID、账号或消息正文。
3. 联系人和会话都包含的群只出现一次；同名但 ID 不同的群仍为两条。会话里查不到同 ID 本地联系人的条目不应成为目标。
4. 若仍只返回 4 个或缺很多群，回传完整脱敏诊断，以及当前微信版本/构建号。不修改未知参数、不请求服务器通讯录、不靠把全部会话 ID 硬塞为可发群“补数量”。
5. “搜索并排除群聊”和自动分配继续使用合并列表。可用 1 条 100 群规则验证预览/缺口/保存，生成和保存仍不发送；不要为测试建大规模真实发送任务。
6. 更换微信账号后旧面板应停止操作；重新读取只显示当前账号的配置和候选，不把两个账号的联系人/会话合并。

## 需要回传

- 「我 → 设置」入口截图、插件首页版本/开关截图（自行遮盖账号和群信息）。
- 新候选群数、是否找到此前缺失群、完整脱敏适配诊断。
- 微信版本和构建号、iOS/机型/注入方式、是否有其他插件。

群池不写死为 3000，真实可读完整性仍需验证；每条约 100/200 群的拆分和手动逐条执行原则不变。随机节拍不保证平台允许或全部送达。实际发送和执行控制 UI 本轮仍未启用。
